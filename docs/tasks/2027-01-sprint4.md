## Must have (in this order)

1. **Protection manifest** (ADR 0003, amended by 0007: one per pipeline repo). `tvt scan` writes `.tvt/protect.json` per pipeline: every hard keep and dormant signal it handles with the consumers that protect it (evidence class, rule or dashboard, owner), owner decisions (keep with a reason and review date, or confirmed drop) and acknowledged gaps. Deterministic output (sorted, no timestamps beyond `generated_at`) so diffs review cleanly. `check` fails when the manifest is older than `max_age_days` (default 7).
2. **`tvt check`** (`pkg/check`). Evaluates the config in a PR against the manifest, offline, with no credentials: apply Prometheus `metric_relabel_configs` regex semantics, Alloy `prometheus.relabel` and `loki.process` stages, and OTel Collector `filter`/`transform` conditions to the protected signal set, instead of guessing intent. Fails when the evaluated drop set touches a protected signal, when a config can't be evaluated (fail closed: unknown processors, Lua/WASM, templating it can't render), on an unacknowledged evidence gap, on a log rule without the error-pattern guard (item 5), and on a drop with no recorded owner confirmation. Property tests: random relabel configs; whenever the evaluated drop set overlaps the protected set, `check` must fail. A GitHub Action wraps it.
3. **`tvt propose`** (`pkg/propose`, `pkg/vcs`). From the JSON report's open recommendations, write the change into each mapped pipeline's repo, one PR per repo: Prometheus `metric_relabel_configs`, Alloy `prometheus.relabel` and `loki.process`, then OTel Collector `filter`/`transform`. Least-lossy order: downsample or reroute before drop; never drop warn and above. Each rule carries a comment with the recommendation's claim and monthly saving. Only mapped signals are proposed (unmapped stays report-only). `--output patch` writes a patch file with no Git token. GitHub first; GitLab only if time remains (first on the cut list).
4. **Owner confirmation and staged drops.** Every drop or label removal names its owner (ownership map, CODEOWNERS, `team`/`service` labels); no owner means report only. The PR opens as a draft assigned to the owner; confirmation is recorded in the protection manifest (and dismissals as keep plus a review date), and only then does the PR leave draft. Drops are staged: reroute to the archive first, drop after the quiet period (default 30 days) with no new reader. Every drop PR is generated with its revert PR.
5. **Error-pattern guard on log rules.** Every generated log drop or sample rule also keeps lines matching `error|exception|traceback|critical|fatal`, in case a stream's level label is wrong. `check` fails a log rule that lacks the guard.
6. **Savings ledger.** Before and after per merged PR: series or bytes and $/month from the scan before the merge and the first scan after it, stored in the graph and shown in the report. This is the MVP gate's evidence.

## Should have

7. **Sampling as an action.** `propose` can keep 1 in N log lines as a step before dropping (Alloy `loki.process` `stage.sampling`, Fluent Bit), with the saving on each rule.
8. **Fluent Bit target.** `grep` Exclude filters for streams and lines, `modify`/`record_modifier` to remove fields, `rewrite_tag` with a second output to reroute; classic `.conf`, YAML, the fluent-bit Helm chart's values and Fluent Operator `ClusterFilter`/`ClusterOutput`. `check` models these filters and fails closed on Lua and WASM.
9. **Recommendation status and the owner queue.** Open, confirmed, or dismissed with a reason; a dismissal writes keep plus a review date to the manifest so tvt doesn't ask again. A capped queue and a weekly digest per owner instead of a stream of PRs.
