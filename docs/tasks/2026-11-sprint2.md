## Must have (in this order)

1. **PromQL extractor** (`pkg/parse/promql.go`). Upstream parser (`parser.NewParser(parser.Options{}).ParseExpr`). Report every selector with matchers, `by`/`without`, `on`/`ignoring`, `group_left`/`group_right` labels, subqueries, and labels created by `label_replace`/`label_join`. Substitute Grafana variables before parsing (`$var`, `${var}`, `${var:csv}`, `[[var]]`, `$__interval`, `$__rate_interval`, `$__range`) and mark the reference **assumed** with the reason. A parse failure is an assumed reference to every metric the text could name, never "unused". Fuzz target plus a corpus test over kube-prometheus mixins and a few public dashboards; print the parse rate and fail CI if it drops below the recorded baseline.
2. **LogQL extractor** (`pkg/parse/logql.go`, ADR 0005, no Loki dependency). Stream selectors, line filters, parsers (`json`, `logfmt`, `regexp`, `pattern`, `unpack`), label filters, `line_format`/`label_format`, `unwrap`, metric queries with `by`/`without`. Separate stream labels from labels extracted by a parser (only stream labels map to `loki:stream:*` signals). Replace the `LogStreamSelectors` stopgap; keep its fuzz corpus.
3. **References in the graph.** Wire both extractors through `scan.Build`: panel targets, template variable queries, annotation queries, Prometheus/Mimir/Loki rules. Label-level detail in `refs` (exact or assumed, reason). Recording-rule chains: a rule's output metric is a signal, so metric → recording rule → alert resolves end to end.
4. **Query logs to references.** Prometheus query log (skip `ruleGroup` lines, already the heartbeat), Mimir query-frontend `query stats` lines (panel attribution from `header_x_dashboard_uid`/`header_x_panel_id`; drop `user_agent=mimir/...`), Loki `metrics.go` lines (`component=frontend`, skip `source=tvt`). Ad hoc use gets the 15-day half-life weight, but the last time each signal was read is stored indefinitely and never decays, so a metric read once nine months ago still shows it. **Proven query log:** a marker query that selects no series, sent with `X-Query-Tags: Source=tvt-probe`, must appear in the log, otherwise that source's coverage is 0 and recorded as a gap.
5. **Grafana-managed alert and recording rules** as consumers: ruler and provisioning APIs, in the token's org. Record datasource, interval and query, and tag `evaluated_by=grafana`. The lab's alert-only metric (`shop_order_export_lag_seconds`) must come out hard-keep.
6. **Hard-keep classification** in `pkg/score`: alert rules, recording rules that feed an alert, Grafana-managed rules, and dashboards viewed in the window. Add an `owner` field (from an ownership map, CODEOWNERS or `team`/`service` labels; empty when unknown) to every hard keep and candidate, and a `dormant` class for unread signals that look incident-critical (error, latency, saturation and queue-depth names, tier 0/1 services, names found in alert `runbook_url` targets). Dormant signals are never drop candidates. Sprint 4 needs both for owner sign-off, so get the schema in now. Golden test over the full lab ground truth: zero misclassified hard keeps, and every seeded dependency resolved.

Then add `grafana.edition: oss | cloud`: Cloud auth (basic auth, instance ID + access-policy token) for cardinality (`<prometheus-http-prefix>/api/v1/cardinality/...`) and rules; a `ViewSource` from Usage Insights (queried through the Grafana data source proxy); Adaptive Metrics per-metric usage counts as query evidence; record a gap for direct Loki API queries. Nightly CI job runs `tvt scan` against the Cloud stack with the secrets above. Usage Insights isn't on the free tier: fixtures come from a trial stack or the first Cloud partner, and the adapter is tested against those.
