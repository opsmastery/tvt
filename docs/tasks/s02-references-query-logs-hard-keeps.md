## Must have (in this order)

1. **PromQL extractor** (`pkg/parse/promql.go`). Upstream parser (`parser.NewParser(parser.Options{}).ParseExpr`). Report every selector with matchers, `by`/`without`, `on`/`ignoring`, `group_left`/`group_right` labels, subqueries, and labels created by `label_replace`/`label_join`. Substitute Grafana variables before parsing (`$var`, `${var}`, `${var:csv}`, `[[var]]`, `$__interval`, `$__rate_interval`, `$__range`) and mark the reference **assumed** with the reason. A parse failure is an assumed reference to every metric the text could name, never "unused". Fuzz target plus a corpus test over kube-prometheus mixins and a few public dashboards; print the parse rate and fail CI if it drops below the recorded baseline.
2. **LogQL extractor** (`pkg/parse/logql.go`, ADR 0005, no Loki dependency). Stream selectors, line filters, parsers (`json`, `logfmt`, `regexp`, `pattern`, `unpack`), label filters, `line_format`/`label_format`, `unwrap`, metric queries with `by`/`without`. Separate stream labels from labels extracted by a parser (only stream labels map to `loki:stream:*` signals). Replace the `LogStreamSelectors` stopgap; keep its fuzz corpus.
3. **References in the graph.** Wire both extractors through `scan.Build`: panel targets, template variable queries, annotation queries, Prometheus/Mimir/Loki rules. Label-level detail in `refs` (exact or assumed, reason). Every ref also carries its **evidence class**: `declared` (an alert, recording rule, SLO or runbook step evaluates the signal), `incident` (reserved for Phase 2's incident timelines) or `observed` (views, query logs). Only observed evidence decays; Sprint 3's report shows the class for every reader. Recording-rule chains: a rule's output metric is a signal, so metric → recording rule → alert resolves end to end. **Resolve patterns against real names:** a `__name__=~` matcher or a name built from a variable expands to every collected metric it matches; a matcher value from a variable (`Matcher.Variable`) resolves to the variable's possible values where the dashboard defines them (custom, constant, `label_values()` against collected label values), else it matches every value. Whatever can't be resolved counts as referenced, assumed. Refs from a query that didn't parse resolve only against collected signals: they must never create a signal for a name that doesn't exist (a fallback can name `and`, `by` or `range`).
4. **Query logs to references.** Prometheus query log (skip `ruleGroup` lines, already the heartbeat), Mimir query-frontend `query stats` lines (panel attribution from `header_x_dashboard_uid`/`header_x_panel_id`; drop `user_agent=mimir/...`), Loki `metrics.go` lines (`component=frontend`, skip `source=tvt`). Ad hoc use gets the 15-day half-life weight, but the last time each signal was read is stored indefinitely and never decays, so a metric read once nine months ago still shows it. **Proven query log:** a marker query that selects no series, sent with `X-Query-Tags: Source=tvt-probe`, must appear in the log, otherwise that source's coverage is 0 and recorded as a gap.
5. **Grafana-managed alert and recording rules** as consumers: ruler and provisioning APIs, in the token's org. Record datasource, interval and query, and tag `evaluated_by=grafana`. The lab's alert-only metric (`shop_order_export_lag_seconds`) must come out hard-keep.
6. **Hard-keep classification** in `pkg/score`: alert rules, recording rules that feed an alert, Grafana-managed rules, SLOs and runbook queries (item 7), external consumers, and dashboards viewed in the window. **External consumers:** remote-write targets, federation and outside tools never show up in logs, so `tvt.yaml` lists them (`external_consumers:`, already in `examples/tvt.example.yaml`: a name plus metric regexes and stream selectors) and each becomes a hard-keep consumer. Add an `owner` field (from an ownership map, CODEOWNERS or `team`/`service` labels; empty when unknown) to every hard keep and candidate, and a `dormant` class for unread signals that look incident-critical. Sprint 2 adds the schema and the name rules: error, latency, saturation and queue-depth names, and signals of tier 0/1 services (a `tier` label or the ownership map). Sprint 3 adds runbook and postmortem mentions and the "dormant: confirm" report rows. Dormant signals are never drop candidates. Sprint 4 needs `owner` and `dormant` for owner sign-off, so get the schema in now. Golden test over the full lab ground truth: zero misclassified hard keeps, and every seeded dependency resolved.
7. **SLOs and runbook queries as declared hard keeps.** Read SLO definitions (Sloth and Pyrra `PrometheusServiceLevel`/`ServiceLevelObjective` files, OpenSLO YAML, and Grafana SLO from its read API) from paths and repos listed in `tvt.yaml` (done: files and checkouts; Grafana SLO moves to item 11); extract each SLI query with the PromQL extractor and add an `slo` consumer, which is hard keep. Read each alert's `runbook_url` (and other annotation links): a runbook step that runs a query (PromQL or LogQL in a code block, or a Grafana Explore or dashboard link) is a declared dependency, so its signals are hard keep; a runbook that only names a signal feeds Sprint 3's dormant rule. Fetch runbooks read-only; an unreachable runbook is a recorded gap. In tvt-lab: add one Sloth SLO over a metric nothing else reads and a runbook with a query step, and put both in `ground-truth.yaml`.

17. **MetricsQL fails safe.** MetricsQL extends PromQL (`WITH` expressions, VictoriaMetrics-only functions), so the PromQL extractor rejects some VictoriaMetrics rules and dashboards. Such a query must become an assumed reference to every metric it names, never "no reference". Add MetricsQL fixtures to the parser corpus, assert they become assumed references, and track the MetricsQL parse rate in the corpus test.
18. **Absence alerts are hard keeps.** A rule using `absent()` or `absent_over_time()` reads its metric and the labels it matches like any other rule, so it's a hard keep, and dropping a label it matches on would fire it. It returns no series by design, so Sprint 6's "rule returned nothing for 30 days" finding must skip it. Add both cases to the parser fixtures, and an `absent()` alert on a shop metric to tvt-lab and `ground-truth.yaml`.
19. **Unknown data sources are assumed readers.** A panel on a data source tvt doesn't parse yet (Pyroscope, Elasticsearch, anything else) records an evidence gap and an assumed reference, and must never make its dashboard look unused. Add a Pyroscope panel to the Grafana fixtures.
